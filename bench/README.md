# bench/ — измерение качества интерпретации

## MingLi-Bench (issue #33, прогон 2026-11-09)

Датасет: DestinyLinker/MingLi-Bench (MIT) — 160 вопросов с выбором из 4 по 32 реальным картам конкурса 全球算命师大赛
2022–2025 («что случилось в 1996?», «в каком году женился?», «какое образование?»…), оценка — точное совпадение буквы,
случайный уровень 25 %. Скрипт `mingli_bench.py` (prepare/score); данные и ответы — в `bench/out/` (в .gitignore).

Два условия, один и тот же агент (OpenCode `general` = GPT-6 Astra, по 32 вопроса на вызов, без интернета и кода):
- **A — наш конвейер**: карта от `bazi.py` (столпы с 十神, сила ХД, 用神/忌神, 调候, Шэнь Ша, interactions, столпы удачи
  с годами, geju; для годов из вопроса/вариантов — 流年-столп, его 十神 и dynamic_interactions) + краткие правила скилла.
- **B — сырая модель**: только данные рождения и вопрос.

| | A (карта + правила) | B (без карты) |
|---|---|---|
| Всего | **84/160 = 52.5 %** | **77/160 = 48.1 %** |
| «что случилось в N году» (n=34) | 20 (59 %) | 24 (71 %) |
| остальные: какой год / каков… (n=126) | 64 (51 %) | 53 (42 %) |
| vs случайные 25 % | p ≈ 9·10⁻¹⁴ | p ≈ 2·10⁻¹⁰ |

Согласие A и B: 103/160 одинаковых ответов; верны оба — 60, только A — 24, только B — 17; McNemar p ≈ 0.35 —
**разница +4.4 п.п. статистически не значима при n=160**. Распределение букв в ответах близко к ключу (без перекоса).

Честные выводы:
1. Карта и правила **не вредят и, видимо, немного помогают** на вопросах без конкретного года (+9 п.п.), но на вопросах
   «что случилось в N году» сырая модель лучше (−12 п.п., n=34): наш блок 流年 (忌神-год → «давление») толкает к негативным
   вариантам, а ключ там часто позитивный; правила скилла писались для чтений, не для угадывания событий.
2. 48 % у модели без карты — подозрительно много для 4 вариантов о чужих биографиях: конкурсные материалы публичны,
   часть ответов может быть в обучающих данных; это ограничение самого бенчмарка.
3. Пояса — допущение по стране (как у бенчмарка); ответы по 32 вопроса на вызов, без CoT — грубее, чем протокол
   авторов (по одному, `--cot`). Цифры годятся для сравнения A↔B внутри прогона, не для таблицы лидеров.

Что менять дальше (если возвращаться): по одному вопросу с рассуждением; в блок 流年 добавить позитивные сигналы
(流年 на 用神, 合 к ветви дня = брак и т. п.) — сейчас правила перекошены в сторону «тени»; прогнать те же 160 через
Джйотиш+ДЧ как доп. голоса — проверить, помогает ли «три системы».
