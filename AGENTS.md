# AGENTS.md

Инструкции для ИИ-агентов, работающих с этим репозиторием (OpenCode, Claude Code и другие). Единственный источник правил: `CLAUDE.md` только импортирует этот файл строкой `@AGENTS.md`.

## Проект: Китайская метафизика

Набор Python-калькуляторов и локальная веб-версия Ба Цзы для систем китайской астрологии/дивинации (Ба Цзы, Ци Мэнь, Цзы Вэй, Мэй Хуа).

**Расширение (2026-06→07): мультисистемный профиль** добавляет Джйотиш, Дизайн Человека, Генные Ключи, Матрицу Судьбы и тибетскую (Джунгци) поверх общего астрономического фундамента на Swiss Ephemeris. Оркестратор — `/profile3`; подробности — в разделе «Профиль по системам» ниже.

**Два слоя:**
- **Расчёты** — Python-модули в этой директории (`bazi.py`, `jieqi.py`, `qimen.py`, `ziwei.py`).
- **Интерпретация** — skill-файлы. Скилы вызывают Python для расчёта и сверху накладывают правила чтения.
  - **Все скилы живут в репозитории** (с 2026-11-09 — единственный источник правды): `skills/<id>/SKILL.md`, id ∈ {`bazi`, `profile3`, `profile3-compare`, `qimen`, `ziwei`, `meihua`, `human-design`, `gene-keys`, `jyotish`, `matrix`, `tibetan`}. Крупные разбиты на ядро + `references/` (вывод skill tool OpenCode обрезается на ~45 КБ): `bazi` — части гайда 01–05 + `bazi-year.md`, `bazi-compare.md`; `profile3` — `batch-mode.md`, `step3-interpreters.md` (здесь «Карта honesty-полей», её читает `verify_honesty_map.py`), `step4-synthesis.md`. `setup.sh` подключает их symlink'ами на папки: `~/.config/opencode/skills/<id>` (OpenCode) и `~/.claude/skills/<id>` (Claude Code; до 2026-11-16 — по одному файлу в `~/.claude/commands/`, без `references/`); подрежимы `bazi-year` и `bazi-compare` остаются командами Claude Code в `~/.claude/commands/`. Главный оркестратор — `profile3`.
- **Мэй Хуа:** арифметику (起卦, 本/变/互/错/综, 体用, 卦气) с 2026-11-09 считает `meihua.py`; тексты и толкование гексаграмм — в markdown-скилле и его `references/hexagrams.md`.

**Репозиторий и установка.** Источник правды — репозиторий проекта; checkout может лежать где угодно — скиллы находят его по symlink'у `~/.bazi` (ставит `setup.sh`) или по `BAZI_DIR`. Личные чтения (`profiles/`, `chart_*`, `Подарок_*`, `year_*`, `calendar_2026/`, `.claude/`) в `.gitignore` и в репозиторий не идут. Правки — коммитом в репозиторий, затем `git pull` на других машинах. Развёртывание на новой машине:
```bash
git clone https://github.com/aumkara/bazi-toolkit.git && cd bazi-toolkit
bash setup.sh   # .venv + pyswisseph + ephem; symlink'и скиллов в ~/.config/opencode/skills и ~/.claude/skills; ~/.bazi → эта папка; хук pre-commit; check_all.sh
```

**Путь к проекту (2026-11-16).** Скиллы берут корень из `${BAZI_DIR:-$HOME/.bazi}`: `~/.bazi` — symlink на корень checkout'а, его ставит и перенаправляет `setup.sh` (если `~/.bazi` уже занят не-symlink'ом, скрипт его не трогает и просит задать `BAZI_DIR`). После переноса папки или на машине, где `git pull` принёс эту правку, — `bash setup.sh --no-check`, иначе скиллы не найдут калькуляторы. Раньше в скиллах был зашит путь одной машины; гард `check_skill_paths` в `check_all.sh` не даёт ему вернуться.

## Структура

- `bazi.py` — ядро Ба Цзы: 4 столпа, скрытые стволы, 10 божеств, сила ХД, 空亡, Шэнь Ша, баланс стихий, столпы удачи.
- `jieqi.py` — солнечные термины (Swiss Ephemeris через `ephemeris.py`, точность ~секунды; приближение Meeus удалено 2026-06-23), расчёт месячного столпа и столпов удачи.
- `qimen.py` — Ци Мэнь Дунь Цзя (9 дворцов, 时家, 拆补, 转盘). 2026-11-09: сверен с kinqimen на 300 досках — 局/地盘/天盘/九星/八门/八神 совпадают после трёх фиксов (元 по 符头 дня, полёт 值使 по номерам дворцов с учётом 中宫, 伏吟 при 甲-часе); известное расхождение оракула — часовой ствол в 中宫 при 值符 дома. Оракулы — `verify_vs_kinqimen.py`, `verify_vs_mingpan.py` (拆补, третий; у mingpan иные врата при 值符=天禽 — школа 《神奇之门》). 置闰 (超神接气, `--method zhirun`, порог `--zhirun-threshold`, по умолчанию 8 — это «девять дней включительно») реализован 2026-11-09 (#24): 局 от термина блока 上元-符头, 闰 после 芒种/大雪; самопроверка `qimen.py --test` (инварианты 2020–2025: 元 = 拆补, 局 только текущего/соседнего термина, 闰-блоки по 15 дней); оракул 闰-решения — Ciallo (JS под node, `verify_vs_ciallo.py`, 153/153 по 局/元/闰/доске; «置閏» kinqimen — эвристика). Порог — по 《统宗》: «девять дней включительно» = разница дат ≥ 8 (ZHIRUN_THRESHOLD = 8).
- `geju.py` — структура 格局 по 月令 (алгоритм и списки благоприятного/неблагоприятного — из `geju.md`, рамка 子平真诠) и сравнение со школой силы; блок `geju` в JSON bazi.py (#29). 从格/专旺/化气 не определяет — только пометки-кандидаты.
- `bazi_reverse.py` — обратный поиск дат по 3–4 столпам (год каждые 60 лет, месяц по точным 节, день по 60-дневному циклу, час с 夜子时 как в bazi.py; несогласованные столпы по 五虎遁/五鼠遁 → причина). MCP `bazi_find_dates`. (#30)
- `meihua.py` — Мэй Хуа И Шу (2026-11-09, #23): 起卦 по числам/моменту (лунная дата — lunar-python или `--lunar`), 本/变/互/错/综, 体/用, 卦气; `--test` сверяет 64 гексаграммы с таблицей §1.4 скилла (там же найден и исправлен перепутанный заголовок строк/столбцов); `verify_meihua_table.py` — против снимка Wikipedia (`oracles/hexagrams_kingwen_wikipedia.json`), 64/64; `verify_vs_mingpan.py` (MCP-сервер mingpan под npx) — формулы 起卦 по числам и моменту, 变/互, 体用: 60/60 (#32).
- `ziwei.py` — Цзы Вэй Доу Шу (Пурпурная Звезда). 2026-11-09: сверен с x-iztro (порт iztro, 716k golden) на 150 картах — 命宫/身宫/局/стволы/14 главных звёзд/四化/вспомогательные совпадают после трёх фиксов (安紫微 за пределами дня 1, 破军 = 天府+10, 天魁/天钺 для 庚); час 子 не сверялся. Оракулы — `verify_vs_iztro.py` и `verify_vs_numerologist.py` (ziwei_cli.py из Numerologist_skills — независимая от iztro реализация, 80/80, #31). JSON содержит `conventions` (晚子时 same_day, 闰月 prev-month, 庚年四化 阳武阴同, что не считается) — каталог споров в docs/conventions.md.
- `web.py` + `web/` — локальная веб-версия Ба Цзы на стандартной библиотеке (2026-11-16, вместо Streamlit-`app.py`): форма → `mcp_server.bazi_chart` → тот же `bazi.py --json`; слушает только 127.0.0.1, проверяет Host/Origin, данные рождения не пишет ни на диск, ни в лог. Новой логики расчёта нет; `web.py --selftest` сверяет ответ с CLI и отказы — в `check_all.sh`.
- `bazi_report.py` — .md-отчёт по карте из JSON калькулятора с выбором разделов (`--sections`, `--charts`, `--list`, `--test`): только факты и оговорки, без толкования; шапка с оговорками и хвост «чего здесь нет» входят всегда. Его же разделы отдаёт веб-версия (галочки на странице), имя файла — `chart_<дата>_<город>.md` (под `.gitignore`).
- `timezones.py` — исторические UTC-смещения городов. С 2026-07-11 основной источник — **IANA tzdb** (`CITY_IANA`, вся история: летнее время, война, распад СССР, LMT; выверено 52 якорями `--test` по Wikipedia/astro21, тест вшит в `check_all.sh`) поверх городских окон `CUSTOM_CITY_PERIODS` (правда, которой нет в зонах IANA: Горький +4 до 24.07.1963, Татария/Сев. Осетия до 1960-х, осень-81—весна-82). `CITY_BASE_TZ` — только поясное до 1930 для этих городов. Оффсеты бывают отрицательные (Нью-Йорк) и дробные (Сеул +8.5) — все CLI-парсеры их понимают. Новый город добавлять в `CITIES` + `geo.LAT` + `CITY_IANA`; `CITY_BASE_TZ`/`CUSTOM_CITY_PERIODS` не трогать. `NOTE` из `historical_utc_offset` с «⚠» — обязательная оговорка чтения.
- `60_pillars.md`, `geju.md`, `tiaohou.md` — справочные данные (архетипы 60 столпов, структуры 格局, 调候用神).
- `chart_*.md`, `Подарок_*.md` (+ `.pdf`) — сохранённые выводы чтений для конкретных людей, **не справочники**. Читать как примеры, не как источник истины.

## Запуск

```bash
cd ~/.bazi        # корень проекта (symlink от setup.sh)

# Локальная веб-версия Ба Цзы (http://127.0.0.1:8765; только стандартная библиотека)
.venv/bin/python web.py

# Ба Цзы (солнечный календарь)
.venv/bin/python bazi.py 1990-05-15 14:30 М UTC+8
.venv/bin/python bazi.py --test              # валидация

# Цзы Вэй (лунный календарь; --stem опционально задаёт ствол года)
.venv/bin/python ziwei.py --lunar 1990 4 15 14 М
.venv/bin/python ziwei.py --lunar 1990 4 15 14 М --stem 6
.venv/bin/python ziwei.py --test             # валидация

# Ци Мэнь (текущий момент или заданный)
.venv/bin/python qimen.py
.venv/bin/python qimen.py 2026-04-21 15:30 UTC+3

# Солнечные термины / столпы удачи
.venv/bin/python jieqi.py 2024 jie
```

Мэй Хуа: `.venv/bin/python meihua.py --numbers 17 29` или `--time 2026-04-08 14:30`; толкование — в скилле `meihua`.

## Профиль по системам (расширение 2026-06→07)

Из (дата, время, место, пол) строит профиль + сравнение простым языком в `profiles/`. **Единственный оркестратор — `/profile3` (ядро из 3 независимых и самых ёмких):** Ба Цзы + Джйотиш + Дизайн Человека → **4 файла** (1_bazi, 2_jyotish, 3_human_design, 4_synthesis). Родственные минорные системы не выброшены, а живут подразделом-веткой в файле своего мажора: Джунгци → в `1_bazi.md`, «Западный взгляд» (тропические Солнце/Луна/асцендент из поля `tropical` jyotish.py) → в `2_jyotish.md`, Генные Ключи → в `3_human_design.md` (ветка ≠ независимое подтверждение — правило честности). Матрицы в ядре нет (числовой корень, самая шаткая; по запросу — `/matrix`). Калькуляторов в прогоне 5 (bazi, jyotish, hd + gene_keys, tibetan для веток); matrix.py профилем не вызывается. **Без времени рождения профиль НЕ строится** — ничего не придумываем (ни полудня, ни прикидок). Обоснование выбора ядра: 3 реальных корня родства (китайский календарный / планетный / колесо ворот) — по самому ёмкому представителю от каждого; `compat.py` уже использует ровно эту тройку. История: 6-системный `/profile6` (2026-06) **УДАЛЁН 2026-07-11**; его старые **7-файловые** выводы (1_bazi … 7_synthesis) в `profiles/<дата>_<город>/` законны — не трогать и не смешивать форматы (профиль тройки при коллизии пишет в `…__3sys/`).

**Астрономический фундамент (общий):**
- `ephemeris.py` — единый источник долготы Солнца через **Swiss Ephemeris (pyswisseph)**. ОБЯЗАТЕЛЕН: без него движок отказывается считать, НЕ падает молча на приближение. Если запущен системным python3 — сам перезапускается под `.venv` (бутстрап). `bazi.py`/`jieqi.py` тоже берут λ☉ отсюда (приближение Meeus удалено; точность 节气 теперь ~секунды против прежних 3.5–13 мин).
- `ephem_core.py` — полная астрономия для систем с эфемеридой: 13 тел, сидерика (аянамша Лахири), точка Дизайна (Солнце−88°), асцендент. Имеет **двойную сверку** swisseph↔PyEphem (слой верификации).
- `geo.py` — координаты городов (широта из таблицы + долгота из `timezones.CITIES`); неизвестный город → честный отказ (нужны координаты).

**Калькуляторы (каждый: `--json` + `--test`):**
- `hd.py` — Дизайн Человека: колесо ворот (выверено), 26 активаций, центры/36 каналов (самопроверка), Тип/Авторитет/Профиль/крест. Конвенция узлов — параметр; при расхождении mean/true выдаёт `convention_warnings`.
- `gene_keys.py` — Генные Ключи: 11 сфер Голограммы + спектр Тень→Дар→Сиддхи + программные партнёры (оппозиция колеса; 32/32 пары сверены с офиц. genekeys.com 2026-07-11). Тонкий слой на `hd.py` (то же колесо). Рус. ярлыки спектра — наш перевод (офиц. рус. канон только в бумаге, Биверсум 2013).
- `jyotish.py` — Джйотиш (2026-11-09: сверен с dashaflow на 140 картах — Лагна со знаком и градусом, знаки 9 грах, накшатра/пада Луны, владыка махадаши совпадают; оракул `verify_vs_dashaflow.py`): Лагна, 9 грах по раши/накшатрам/домам, Вимшоттари маха+антар даша, базовые йоги. Конвенции: Лахири + знаковые дома + Вимшоттари + средний узел. Плюс поле `tropical` («западный взгляд», добавлено 2026-07-11): тропические Солнце/Луна/асцендент с `near_cusp` — мостик к привычному западному гороскопу; НЕ отдельная система (тот же расчёт, сдвиг = аянамша; тождество проверяется в `--test` п.7 с якорем «6 мая = Телец»; п.8 — внешние AA-якоря Astro-Databank по Солнцу/Луне/асценденту, вкл. LMT-ветку 1879, допуск 3′).
- `matrix.py` — Матрица Судьбы (Ладыни 2006): ЯДРО на 22 арканах (день/месяц/год/сумма/центр). Полная октаграмма НЕ реализована (формулы проприетарны/вариант-зависимы).
- `tibetan.py` — Джунгци (byung rtsi), **уверенность средняя-высокая**: год-животное+стихия, Меуа и ВСЕ 5 сил выверены (2026-07-11: Лю/Лунгта добраны по трём независимым линиям — Erlewine/astrotibet·Белый Берилл/Nine Ways·Бон, 300 кросс-проверок по двум 60-летним таблицам); обструктивные годы (ло-скаг выверен, дун-зур средняя); **Лосар резолвится точной таблицей** (Пхугпа 1900–2100, вшита 2026-07-15: Janson Table 1 + код Хеннинга, 121 дата печатно + анонсы ЦТА; провенанс `losar_provenance/`) — блок `losar` в JSON, второй вариант (`alt_if_before_losar`) только на краях (день Лосара / расхождение Пхугпа↔Цурпху / вне таблицы); `--as-of` для детерминированного пересчёта. Натальная Паркха (нужен возраст матери) и прочие «тёмные» годы (1 источник) честно НЕ выданы — помечено в `not_computed`/`honesty_note`.
- `verify_all.py` — ЧИСТЫЙ тест движков на зашитом тест-рождении: golden всех калькуляторов + кросс-системные тождества (HD Солнце=Gene Keys Life's Work; Ба Цзы=Джунгци по животному; два движка <3′; geo→Лагна). Гейт перед каждым прогоном на пользовательских данных; вывод в чтение НЕ идёт — оговорки чтения только из honesty-полей клиентских JSON.
- `verify_vs_lunar.py` — внешний оракул для bazi.py: четыре столпа против lunar-python на 300 случайных + граничных моментах (UTC+8, без солнечной поправки). Без установленного `lunar_python` — пропуск с exit 0; известное расхождение конвенций 夜子时 (ствол часа 23:xx) считается отдельно (issue #16). Обзор похожих проектов и что из них брать — `docs/related_projects.md` (2026-11-09).
- `docs/sources.md` — реестр источников, на которые ссылаются код и справочники, со статусом каждого ([факт] / [факт традиции] / [интерпретация] / [спекуляция]); правило: имя классика = школа, не цитата. `docs/conventions.md` — споры школ и переключатели.
- **2026-11-09, солнечная полночь:** `timezones.true_solar_datetime` возвращает дату; `bazi.py --city` берёт столп дня от солнечных суток (`input.solar_date`, `input.solar_day_shift`), настенная дата остаётся в `input.date` (контракт персиста/recheck не меняется). До фикса рождённые 00:xx–01:xx западнее меридиана пояса получали Хозяина Дня настенной даты — 4 локальных профиля перегенерируются (#28). Найдено агентом в прогоне regen28 (DIAG_solar_midnight.md).
- `recheck_profiles.py` — после фиксов движков: какие сохранённые чтения в `profiles/` устарели. Отбирает кандидатов по штампу `_engines.sha`, пересчитывает JSON текущим кодом с фиксацией даты (`--as-of` из персиста, вход — настенное время/город/пол из `_bazi.input`, не солнечное), сравнивает НАТАЛЬНЫЕ поля, схемные расхождения (age_end, as_of, conventions) игнорирует. Выход 3 = есть что перегенерировать. Данные людей не покидают машину.
- `fact_check_reading.py <папка профиля>` — гейт Шага 3.5 profile3: все упомянутые в тексте 干支/十神/ворота/каналы/Тип/Профиль/Лагна/накшатра обязаны быть в JSON; условные и «отсутствующие» упоминания допустимы.
- `check_all.sh` — **одна кнопка**: батарея из 30+ шагов — окружение, размеры и пути скиллов, golden и кросс-тождества движков (`verify_all.py`), `--test` калькуляторов, отчёт и веб, формат ошибок CLI, гейт утечек, внешние оракулы. Полный перечень — в самом скрипте. Оракул без установленной библиотеки пропускается с кодом 0 — пропуск не равен сверке (CI требует оракулы флагом `--require`). Три сверки, которые скачивают и выполняют сторонний код (Ciallo под node, mingpan через npx, `ziwei_cli.py` с GitHub), запускаются только с флагом `--network` или переменной `BAZI_NETWORK_CHECKS=1`: обычная установка не выполняет чужой код без явного согласия; CI флаг включает. Не входят: `jieqi_oracle.py` и `losar_provenance/verify_vs_janson.py` (нужны внешние файлы), `verify_bazi_md.py` (разовая сверка 2026-07-01). Прогоняй после ЛЮБОЙ правки кода; выход 0 = всё зелёное.

## Качество чтений

Правила интерпретации — OVERRIDE дефолтного поведения. Полная версия — раздел «Качество чтений» скилла `bazi`. Краткая сводка:

1. **Без подслащивания.** 忌神 = проблема. 冲 = удар. 空亡 = пустота. Плохой период = «сиди тихо».
2. **Не выдумывать классику.** Не цитировать 滴天髓/穷通宝鉴 конкретными пассажами без уверенности. Говорить «по логике школы X».
3. **Не считать в уме.** ВСЕГДА запускать bazi.py / jieqi.py. Интерпретация — только после калькулятора.
4. **Расхождения школ.** Когда 旺衰派/格局派/盲派 дают разное — называть обе версии.
5. **Не переинтерпретировать.** Слабое взаимодействие = слабое. «Не уверен» — допустимый ответ.
6. **Не психологизировать без запроса.** Классика первой, психология — только по просьбе.
7. **Обязательные секции после чтения:** блок «Тень» (что смягчил, что проблемного) + маркеры уверенности [факт] / [интерпретация] / [спекуляция].
