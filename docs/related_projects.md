# Похожие проекты: что у них есть и что взять (2026-11-09)

Ответ на issue #1. Поиск: GitHub/PyPI/веб по запросам «bazi calculator library», «bazi MCP», «jyotish python swisseph», «human design calculator open source», «iztro», «tibetan calendar phugpa», «kinqimen», «Claude Code skill bazi». Просмотрены README и описания ~35 проектов; подробно разобраны те, что либо считают то же, что и мы, либо упаковывают расчёт для LLM так, как это делаем мы. Числа звёзд — на дату поиска, по данным GitHub в выдаче; где их не было, стоит «—».

Чтобы сравнение не осталось словами, один приём из найденного применён сразу: `verify_vs_lunar.py` сверяет четыре столпа `bazi.py` с независимой библиотекой **lunar-python** на 300 случайных моментах 1900–2050 + 9 граничных (Личунь 1990/2024 с точностью до минут, полночь, 晚子时). Результат: **299/309 совпали, настоящих расхождений 0**, 10 расхождений — все в одном месте: ствол часа для 23:00–23:59 (см. §4, п. 1).

## 2. Где мы сильнее (сохранить)

1. **Исторические пояса СССР/России и истинное солнечное время как обязательный шаг** (`timezones.py`: IANA + городские окна, 56 якорей, LMT до-поясной эпохи, `⚠`-NOTE в JSON). Ни один из найденных проектов не решает советское декретное/летнее время; большинство берёт пояс «как есть» или просит долготу.
2. **Honesty-поля в самом JSON** (`boundary_warnings`, `yongshen_borderline`, `tz_note`, `convention_warnings`, `fragile_activations`, `losar.bazi_divergence`…) и механическая сверка карты полей скилла с выводом движков (`verify_honesty_map.py`). У ruthless-coder есть предупреждения, у остальных — нет.
3. **Арифметика независимости систем** («два входа, три языка; ветка ≠ подтверждение») — bazaar-of-fates и yuan складывают 6–13 систем без этого различения.
4. Swiss Ephemeris для 节气 (точность секунды), двойная сверка swisseph↔PyEphem в `ephem_core.py`, Личунь как граница прогнозного года.
5. Русский язык, «без подслащивания», обязательная «Тень» и три уровня уверенности — в этой нише аналогов нет.

## 3. Где мы слабее (честно)

1. **Нет внешних оракулов в `check_all`**: все тесты — собственные golden. Сегодняшний прогон против lunar-python — первый.
2. **Разногласия школ не конфигурируются** и не всегда объявлены в выводе: 晚子时, база 神煞 (日干 vs 年干), версия 天乙贵人, 羊刃 для инь-стволов, школа 用神 — у нас зашиты по одному варианту.
3. **Нет упаковки**: ни `pip`, ни MCP, ни CI; зависимости не зафиксированы (#6), абсолютный путь (#5).
4. **Покрытие**: 神煞 — 7 + 红鸾/天喜 (у fortune-assistant 18, FOR-BAZI 20+); 格局 считается не кодом, а гайдом; нет 流月/流日, 胎元/命宫, обратного поиска даты по столпам; `ziwei.py` без внешней сверки; `qimen.py` только 拆补.
5. **Знания без провенанса**: `geju.md`, `60_pillars.md`, `tiaohou.md` не указывают источник по утверждениям (0xf3cd/bazi и bazi-master делают это на уровне каждой записи).
