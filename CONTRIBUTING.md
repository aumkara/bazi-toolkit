# Как помочь проекту

Проект ведёт один человек в свободное время: сроков ответа нет, но сообщения об ошибках и исправления приветствуются.

## Сообщить об ошибке

Откройте issue и приложите:

1. точную команду и её вывод (или шаги на веб-странице);
2. версию из `CHANGELOG.md` и версию Python;
3. чего вы ожидали и откуда это ожидание — другая программа, книга, школа.

**Не присылайте данные рождения реальных людей** — ни свои, ни чужие. Ошибку почти всегда можно показать на
вымышленной дате; если она проявляется только на конкретной, сдвиньте год или опишите условие («за 5 минут до
границы часа», «родился до Личуня»). Issues публичны и удалению из чужих копий не поддаются.

Расхождение со школой — не всегда ошибка: сначала посмотрите `docs/conventions.md`, там перечислены спорные места
и переключатели.

## Предложить исправление

```bash
git clone https://github.com/aumkara/bazi-toolkit.git && cd bazi-toolkit
bash setup.sh --no-skills        # окружение, хук pre-commit и вся батарея проверок
# ...правки...
bash check_all.sh                # должно быть «всё зелёное»
```

Затем обычный pull request. Чтобы его было легко принять:

- **Считает код, а не текст.** Новое число — в калькуляторе и в его `--test`; скилл только читает JSON.
- **Оговорки — в JSON.** Если результат зависит от конвенции или неточен у границы, это отдельное поле, а не
  примечание в документации.
- **Источник.** Для таблиц и правил — запись в `docs/sources.md` со статусом [факт] / [интерпретация] /
  [спекуляция]. Тексты под несовместимыми лицензиями не копируем.
- **Только нейтральные даты** в тестах, примерах и скиллах (в проекте принята 1990-05-15). Хук `pre-commit`
  остановит коммит с домашними путями, адресами почты и токенами, но чужую дату рождения он не узнает — за этим
  следит автор правки.
- **Контракт.** Меняете формат JSON, флаги или коды возврата — добавьте запись в `CHANGELOG.md`.
- Один pull request — одна тема. Раскладку файлов и способ установки без обсуждения в issue не меняем.

## Лицензия вкладов

Отправляя pull request, вы соглашаетесь, что ваш вклад распространяется под лицензией проекта —
GNU AGPL версии 3 или более поздней (`LICENSE`). Сторонние данные допустимы только с указанием источника и лицензии.

## Безопасность

Об уязвимостях — не в открытых issues, а по инструкции из `SECURITY.md`.
