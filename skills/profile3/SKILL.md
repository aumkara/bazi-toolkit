## Почему 3 и что с «ветками»

Ядро — три самых ёмких системы. Честная арифметика независимости: **два независимых входа** — календарь (Ба Цзы) и небо (Джйотиш и Дизайн Человека смотрят на ОДНИ И ТЕ ЖЕ положения планет, читая их несвязанными способами) — и **три независимых языка толкования**; «три независимых корня» было бы слаще правды (та же формула — в памятке синтеза, Шаг 4). Родственные минорные системы НЕ выбрасываются, а живут **подразделом-веткой внутри файла своего мажора**:
- **Джунгци (тибетская)** → подраздел в `1_bazi.md` (родственный календарный корень: год-животное ОБЫЧНО совпадает с годом Ба Цзы, но границы года разные — Ба Цзы режет по солнечному Личуню, Джунгци по Лосару; tibetan.py резолвит год по ФАКТИЧЕСКОЙ дате Лосара (Пхугпа, таблица 1900–2100), поэтому в окне МЕЖДУ границами знаки двух систем законно РАЗНЫЕ — это два календаря, не ошибка. Окно ДВУНАПРАВЛЕННОЕ: обычно Личунь→Лосар, изредка зеркально Лосар→Личунь (Лосар случается и раньше Личуня); оба направления флагует сам код — поле `losar.bazi_divergence`; см. Лосар-правило Шага 3);
- **«Западный взгляд»** → подраздел в `2_jyotish.md` (тот же планетный корень: тропические Солнце/Луна/асцендент из поля `tropical` — даже не отдельный расчёт, а тот же в другом отсчёте круга; мостик к привычному «я Близнецы»);
- **Генные Ключи** → подраздел в `3_human_design.md` (буквально тот же расчёт и то же колесо, другой — контемплятивный — язык).

**Ветка ≠ независимое подтверждение.** Совпадение мажора со своей веткой — не «два голоса»: у западного взгляда это буквально ТОТ ЖЕ расчёт, у ГК — то же колесо, у Джунгци — общий календарный корень (совпадение почти всегда, КРОМЕ окна Личунь↔Лосар). Это правило обязано соблюдаться и в файлах, и в синтезе. Матрицы Судьбы в этом профиле нет совсем (числовой корень, самая шаткая содержательно; по явной просьбе — отдельный скилл `/matrix`).

## Аргументы

Формат (любой человек; в Claude Code — `/profile3 …`, в OpenCode — просто в сообщении): `ГГГГ-ММ-ДД ЧЧ:ММ М|Ж ГОРОД`. **Город обязателен** (несёт исторический пояс и солнечную поправку): города нет — расчёт не начинаем, спроси город рождения. ⚠ Солнечная поправка может перенести рождение через полночь (запад от меридиана пояса: 00:xx–01:xx → предыдущие сутки; восток: 23:xx → следующие) — тогда `_bazi.input.solar_day_shift ≠ 0`, столп дня и Хозяин Дня берутся от солнечной даты; это обязательная строка Тени `1_bazi.md` и синтеза (до 2026-11-09 код держал настенную дату — такие профили перегенерируются).
**Список (пакетный режим):** несколько записей по одной на строку — обрабатываю строго ПОСЛЕДОВАТЕЛЬНО, без смешивания (см. «## Пакетный режим»).

**ДАННЫЕ — ТОЛЬКО явный ввод из запроса.** Режима «моя карта» НЕТ (упразднён 2026-07-11 вместе с `user.yaml`): скилл не читает и не создаёт файлов с данными рождения; «про меня» без данных → попроси назвать дату/время/пол/город. **НИЧЕГО не сохраняй в переиспользуемые хранилища**: не создавай `user.yaml`, не записывай данные человека в скилл/память (персист `_*.json` в папку вывода profiles/ — «Куда сохранять» — законный ВЫВОД прогона, не «сохранение данных»). Чего не хватает — **спроси**, не выдумывай. (Реальный случай: тихая подмена чужих времени и пола перевернула Лагну, Профиль и Авторитет. «Чьи данные / время / пол» решают больше расчёта.)

Перед расчётом подтверди вслух — эхом в начале ответа, без ожидания, если данные полны и однозначны: **чьи данные, точную дату и ВРЕМЯ (минуты, AM/PM), пояс/город.** «00:00»/«12:00» — частые архивные заглушки «время неизвестно», а «7:30» без явного 24-часового формата двусмысленно: такое СНАЧАЛА переспроси, молча не принимай. **Критерий двусмысленности времени:** ввод, поданный по формату команды (`ЧЧ:ММ` в строке `/profile3`), считай 24-часовым; переспрашивай, когда время пришло свободным текстом или из архивного источника («в полвосьмого», бирка без формата). **Времени нет — профиль НЕ строим и ничего не придумываем** (ни полудня, ни прикидок): Тип/Авторитет ДЧ и Лагна Джйотиш без времени — гадание. Скажи это прямо и предложи добыть время (бирка роддома, архив ЗАГС, расспросить родных) или ректификацию; без времени честны только одиночные `/tibetan` и `/bazi` (тот сам уронит часовой столп) — но это уже НЕ этот профиль.

**Точность времени критична ДАЖЕ когда время указано.** Окно бери из `time_window.json`: это ПЕРВАЯ оговорка ВСЕГДА, при любом запасе — в Тени файлов 1–3 по своим показателям и первой строкой списка перевёртышей синтеза. Если любой числовой запас `stable_window_core.minutes_before/after` <30 минут (включая 0, исключая `null`) — вынеси ещё в «Самое главное» с предложением ректификации и тем, ЧТО меняется (значения `earlier`/`later`). `null` — переход не найден внутри окна поиска, не бесконечная устойчивость. `fragile_activations`/`fragile_spheres` остаются для линий/сфер; конвенции узлов — отдельная оговорка.

**Приблизительное время («около»/«примерно»).** Вместо ручных 3–5 точек запускай `time_window.py --span МИНУТ` под названную вилку (до дальнего края, минимум 10); вилку не назвали — уточни. Развилки из JSON веди двумя вариантами в одном прогоне, предложи ректификацию. Вилка шире ~±2 ч — времени нет, профиль не строим. Сетка может пропустить краткий возврат внутри шага: `honesty_note` передай в Тень, не объявляй проверку ректификацией.

## Шаг 1. Разобрать вход и резолвить место

`DIR="${BAZI_DIR:-$HOME/.bazi}"` (код; `~/.bazi` — symlink на корень проекта, его ставит `setup.sh`). Дата/время/пол/город — из явного ввода (см. «Аргументы»); чего-то нет → спроси, **ничего не сохраняй**.

Получи смещение UTC (исторически верное) и координаты:
```bash
DIR="${BAZI_DIR:-$HOME/.bazi}"
"$DIR/.venv/bin/python" -c "import sys; sys.path.insert(0,'$DIR'); \
from timezones import historical_utc_offset; from geo import resolve; \
off,note=historical_utc_offset('ГОРОД',ГОД,МЕС,ДЕНЬ); lat,lon=resolve('ГОРОД'); \
print(f'OFFSET={off} LAT={lat} LON={lon} NOTE={note}')"
```
Оффсеты исторически честные: зарубежные города и постсоветское время — IANA tzdb (летнее время и все переходы учтены), советская эпоха — выверенные городские окна (Горький/Татария/Осетия жили на МСК+1). `OFFSET` бывает **отрицательным** (Нью-Йорк −5) и **дробным** (Сеул до 1961 = +8.5) — калькуляторы это понимают; знак и точку не «чини».
**`NOTE` с «⚠» — обязательная оговорка чтения** (в день рождения переводили часы; оккупация 1941–43; спорная дата перехода области на МСК; Донецк-2014; до-поясная эпоха — для неё код с 2026-07-18 берёт местное среднее время ПО ДОЛГОТЕ ГОРОДА, не референса зоны, и говорит это в NOTE с «⚠»): передай её агентам Шага 3 текстом как top-оговорку для Тени; если она ставит под вопрос столп/Лагну/Тип — то и в `4_synthesis.md`. NOTE и персистится кодом: при `--city` bazi.json несёт её в `input.tz_note` — оговорка переживает компакцию и месяц (принцип «оговорки живут в JSON» теперь без исключений).
Если город не в базе — `resolve` бросит ошибку; НЕ подставлять выдуманные координаты молча. **Исторические имена городов резолвит КОД, не память модели**: `timezones.CITY_ALIASES` (Ленинград→Санкт-Петербург, Горький→Нижний Новгород, Свердловск, Куйбышев, Молотов, Сталинград… — 20 имён) вшит в `historical_utc_offset`/`geo.resolve`/`bazi --city`, резолв уходит в NOTE; имени нет в алиасах — добавь его В КОД (не дубль-запись в CITIES: дубль обошёл бы городские окна `CUSTOM_CITY_PERIODS`). **Город-тёзка** (Мирный и т.п.) — спроси у пользователя РЕГИОН, сам не выбирай. Добавление действительно нового города (данные — из проверяемого источника; СООБЩИ пользователю о правке): `timezones.CITIES` (текущий оффсет, долгота — знак сверь дважды, меридиан) + `geo.LAT` (широта) + `timezones.CITY_IANA` (зона IANA — источник исторических оффсетов) + **ОБЯЗАТЕЛЬНЫЙ якорь на новый город в `timezones._test`** (иначе `--test` его не покрывает — правило 2026-07-18). `CITY_BASE_TZ` и `CUSTOM_CITY_PERIODS` НЕ трогай — они только для советских городов с правдой вне зоны IANA. После ЛЮБОЙ правки timezones/geo прогони `python3 "$DIR/timezones.py" --test` (56 якорей + алиасы + до-поясные; юнит timezones входит и в verify_all — но полный `--test` прогони всё равно). Проверяемых данных нет → спроси, не выдумывай.

## Шаг 2. Посчитать 3 системы + 2 ветки (JSON) + проверить

**`verify_all.py` обязателен, но это ЧИСТЫЙ ТЕСТ ДВИЖКОВ** на зашитом тест-рождении — гейт при КАЖДОМ прогоне: PASS → считай дальше; FAIL → чини, не интерпретируй сломанное число. Его вывод (включая golden-значения) к этому человеку НЕ относится и в чтение НЕ идёт совсем — значения карты бери ТОЛЬКО из JSON этого человека. ВСЕ оговорки чтения живут в honesty-полях JSON ЭТОГО человека (карта полей по движкам — в Шаге 3) — интерпретаторы обязаны транслировать их в Тень; поля веток (Джунгци, ГК) идут в файл их МАЖОРА.

⚠️ **Предупреждения-«перевёртыши» — в общий портрет, не только в Тень файла.** Если предупреждение из JSON человека МЕНЯЕТ результат (node-чувствительность → Тип/Авторитет; аянамша/дома → Лагна) — вынеси и в `4_synthesis.md`.

## Качество (конспект глобальных правил + чек-лист для спот-чеков — для всех 4 файлов)

- **Без подслащивания.** Проблемное называть проблемным. У каждого позитива — тень.
- **Не выдумывать.** Чего нет в JSON — того нет. Спорные конвенции (узлы ДЧ, аянамша/дома) — называть, не выбирать тихо.
- **Происхождение честно.** Современные системы (ДЧ 1987, ГК 2009) не выдавать за древние.
- **Ветка ≠ подтверждение.** Родственное эхо всегда помечать как эхо.
- **Годовой прогноз = окна и сигналы, не обещания.** Текущий год — по дате запуска.
- **Текст каждого чтения завершается «Тенью»** (после неё допустим только блок графиков Шага 4.5); синтез завершается «Тенью синтеза» и «Что дальше». Везде маркеры [факт]/[интерпретация]/[спекуляция].
- **«Карты»/«столпы»/балансы — markdown-таблицами**, НЕ ASCII в код-блоках (иероглифы двойной ширины ломают выравнивание в PDF).
- **В файлах 1–3 иероглифы — ВСЕГДА с русским рядом** («Огонь+ Прямое Богатство», не «丙 正财»).
- **Синтез — строже всего: ни иероглифа, ни номера, ни спецтермина** (полное правило — в Шаге 4).
- **Анти-барнум (issue #19).** Утверждение годится в чтение, только если оно ЛОЖНО для большинства людей: «иногда ты сомневаешься в себе» — мусор; «в споре ты скорее замолчишь и уйдёшь, чем повысишь голос, и потом неделю доигрываешь разговор в голове» — проверяемо. Перед записью каждого тезиса портрета спроси: кто бы с этим НЕ согласился? Нет такого человека — тезис вычеркнуть. То же для прогноза: «год перемен» — мусор, «окно смены работы — весна, риск — осенний конфликт с руководителем» — сигнал.
- **Плохие новости — по процедуре, не вскользь и не с подушкой:** (1) факт из JSON словами; (2) что это значит в быту; (3) что делать; (4) чего НЕ делать; (5) чем это НЕ является (не диагноз, не приговор, не «проклятие»). Смягчающие вводные («но зато», «впрочем, не всё так плохо») запрещены — тень называется тенью.

## Куда сохранять

Папка результатов: `$DIR/profiles/<ГГГГ-ММ-ДД>_<Город>/` (создай). Это ВЫВОД, не данные пользователя.

**Не перетирай чужой вывод.** «Другой ли это прогон» определяй сверкой блока `input` в `_*.json` прежней папки — **время сверяй по НАСТЕННОМУ**: `_bazi.input.wall_time` + `city` (с 2026-07-18), а НЕ по `_bazi.input.time` — оно истинное солнечное и с настенным вводом законно расходится (солнечная ловушка: иначе здоровый архив выглядит «другим прогоном»); в старых персистах без `wall_time` настенное время бери из `_hd.json`/`_jyotish.json` (`birth_local`). Та же дата ≠ тот же прогон: другое время/пол = другой человек или ректификация; `_*.json` в папке нет, а 4 `.md` есть — это ПРЕРВАННЫЙ прогон (упал между `.md` и персистом): примени критерий «свежий И завершён Тенью» из Шага 3 и допиши персист, дубль-папку не форкай; расхождение времён «того же человека» назови пользователю как вопрос ректификации:
- Повторный прогон на ТЕ ЖЕ данные, когда прежний вывод нужно сохранить → суффикс `__run-<ГГГГ-ММ-ДД>`; метка `run-` обязательна — без неё `check_public.py` примет дату прогона за дату рождения и заблокирует коммиты.
- Папка занята ДРУГИМ прогоном (другой человек/время/пол, ректификация) → суффикс `__<время>_<пол>` (схема: `<дата>_<город>__<ЧЧММ>_<пол>/`; вместе со старым форматом ниже порядок: `__<ЧЧММ>_<пол>__3sys`).
- **В папке лежит старый 6-системный профиль** (признак: `7_synthesis.md`) → НЕ смешивай форматы: пиши в `<дата>_<город>__3sys/`. Старые 7-файловые профили — законный вывод удалённого /profile6, их не трогаем.

Файлы: `1_bazi.md`, `2_jyotish.md`, `3_human_design.md`, `4_synthesis.md`.

**Плюс персисти входные JSON и штамп версии движков** (воспроизводимость; спот-чек можно повторить через месяц; после баг-фикса кода затронутые профили ищутся механически):
```bash
DIR="${BAZI_DIR:-$HOME/.bazi}"; TMP="<literal-путь из echo Шага 2>"   # ← оба <…> замени РЕАЛЬНЫМИ значениями
OUT="$DIR/profiles/<папка вывода>"
[ -f "$OUT/4_synthesis.md" ] || { echo "⛔ OUT не похож на папку вывода этого прогона — СТОП, проверь подстановку"; exit 1; }
diff <(python3 -c "import json;print(json.load(open('$TMP/hd.json'))['input'])") \
     <(python3 -c "import json;print(json.load(open('$OUT/_hd.json'))['input'])") >/dev/null 2>&1 \
  || [ ! -f "$OUT/_hd.json" ] || { echo "⛔ OUT — ЧУЖАЯ валидная папка (input _hd.json ≠ этому прогону) — СТОП"; exit 1; }
for f in bazi jyotish hd gene_keys tibetan time_window; do cp "$TMP/$f.json" "$OUT/_$f.json"; done
{ date +%F; shasum -a 256 "$DIR"/*.py; } > "$OUT/_engines.sha"   # штамп: дата прогона + отпечатки калькуляторов
```
**Штамп — ТОЛЬКО в заходе прогона.** Ретро-доштамповка старой папки текущим `_engines.sha` ЗАПРЕЩЕНА: она создаёт слепое окно (папка выглядит пересчитанной кодом, которым не считалась) до следующей правки кода. Старую папку без штампа чинит только честный пересчёт по (б) + перегенерация затронутого чтения.
Штамп работает в паре с `_*.json`: после баг-фикса (а) кандидаты = профили, где отпечаток изменившегося `*.py` старый (глоб нарочно шире 5 движков — реальные фиксы жили в зависимостях вроде timezones.py); (б) точная проверка = пересчитать JSON текущим кодом С ФИКСАЦИЕЙ ДАТЫ и сравнить с сохранённым, **вход для пересчёта бери из персиста правильно**: настенное время и город — `_bazi.input.wall_time`/`city` (старые персисты: `birth_local` из `_hd`/`_jyotish`; город — из имени папки через Шаг 1), пол — `_bazi.input.gender`; **солнечное `_bazi.input.time` обратно в CLI НЕ подавать** (двойная солнечная поправка); у bazi/jyotish есть `--as-of ГГГГ-ММ-ДД`, у tibetan — `--as-of`/`--year` (дату бери из сохранённого JSON: jyotish `dasha_as_of`, bazi `current_year`, tibetan `forces_year_relation.year`; **для bazi годится любая дата сохранённого года** — резолв Личуня внутри года устойчив вне граничных дней) — тогда date-зависимые поля совпадают сами и исключать ничего не надо; hd и gene_keys от даты запуска не зависят, сравниваются как есть — иначе ложное «расхождение» на любом профиле уже назавтра после прогона; **сравнивай и СОСТАВ полей — добавленные/исчезнувшие поля тоже расхождение** (после фиксов движки нередко именно ДОБАВЛЯЮТ поля); расхождение в НАТАЛЬНЫХ полях → чтение перегенерировать. Работает только вперёд: до-штамповые папки так и остаются без версии.
